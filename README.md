# Parsing

Гибридный шлюз данных: универсальный сборщик контента + AI-скаут UGC-креаторов.

## Что готово

- **Контракт данных** — `src/core/contract.ts`: единый `ContentItem` для любого источника.
- **Хранилище ключей** — ключи шифруются (AES-256-GCM) перед записью в Postgres.
- **Роутер ключей** — `src/keys/router.ts`: выбирает ключ с наибольшим остатком квоты,
  на 429 ставит ключ на паузу, на 401/403 помечает недействительным, на 402 — исчерпанным,
  и пробует следующий. Использование: `withKey(db, "firecrawl", async (key) => …)`.
- **Сверка лимитов** — для Apify, Firecrawl и OpenRouter остаток запрашивается у провайдера;
  у остальных считается локально по вызовам.
- **Сборщик** — `src/collect`: `collect(db, target)` для страницы, профиля или хэштега Instagram.
  Страница сначала скачивается локально и бесплатно (прямой запрос, затем Scrapling);
  Firecrawl подключается, только если локально не получилось. Instagram идёт через акторы Apify;
  стоимость каждого запуска записывается в учёт квоты. Результат вместе с сырым ответом сохраняется
  в `content_items`. Повторный запрос берётся из кэша (страницы и профили — 24 ч, хэштеги — 6 ч),
  а один и тот же сбор нельзя запустить дважды одновременно. Проверить вручную — страница `/collect`.
- **Поиск креаторов и аффилиатов** — `src/search`, страница `/search`. Воронка:
  1. посты по хэштегам;
  2. бесплатный отбор по тексту (магазины, агентства, платформы, стоп-слова отсеиваются сразу);
  3. профили только лучших — одним запуском актора, переиспользуются 7 дней;
  4. активность: пост за 14 дней — активный, 15–30 — засыпает, больше 30 — отсев;
  5. бесплатное обогащение со страниц link-in-bio (`src/enrich`): email с источником, портфолио,
     партнёрские витрины (Amazon, LTK, ShopMy…), аккаунты в других сетях, прайс на UGC;
  6. проверка email без отправки писем: синтаксис, почтовый домен, одноразовые и общие адреса;
  7. визуальный аудит лучших (`src/audit`): коллаж постов оценивает модель с поддержкой изображений.

  Три независимых индекса 0–100: **Fit** (ниша + роль автора; режим «аффилиаты» ставит во главу
  витрины и промокоды), **Readiness** (email 40, свежесть 30, прайс 20, портфолио 10) и **Quality**
  (аудит). «Готовый лид» — активный автор с личным email и качеством от 70. Поиск идёт в фоне,
  прерванный продолжается без повторной оплаты. Экспорт: полный CSV и CSV для рассылки.
- **Соответствие GDPR в коде**: у каждого контакта хранится источник и дата; кнопка «Виключити»
  удаляет все данные автора и заносит его в список исключений (email — только хешем), после чего
  он больше не собирается. Профили, где главные герои — дети, отклоняются аудитом.
- **Дашборд** (`/keys`, украинский интерфейс) — ключи, остатки, состояния, добавление
  своих OpenAI-совместимых агрегаторов, статистика вызовов за 7 дней.

## Запуск на ноутбуке (база в Supabase)

**Windows, в один шаг:** скачайте `desktop/Install.cmd` и запустите двойным щелчком. Он поставит
Git и Node.js, если их нет, загрузит проект в `%USERPROFILE%\Parsing`, спросит адрес проекта
Supabase, пароль базы и пароль дашборда, создаст ярлык и откроет дашборд.

**Вручную.** Нужны Node.js 22.12+ и Git. В папке проекта:

```bash
npm install
npm run setup      # спросит строку подключения Supabase и пароль дашборда, проверит связь
npm run shortcut   # ярлык «Parsing» на рабочем столе
```

`npm run setup` достаточно адреса проекта (`https://….supabase.co`) и пароля базы: регион он
найдёт сам, а спецсимволы в пароле закодирует. Можно вставить и готовую строку подключения
(Supabase: **Connect** → **Session pooler**). `MASTER_KEY` создаётся автоматически.

Двойной щелчок по ярлыку применяет миграции (таблицы в Supabase создаются сами), при первом
запуске собирает приложение, поднимает сервер и открывает http://127.0.0.1:3000. После `git pull`
ярлык сам пересоберёт и перезапустит. Остановить — `npm run launch -- --stop`. Журнал —
`data/server.log`.

Приложение работает на ноутбуке, в Supabase лежат только данные. На всех таблицах включён RLS без
политик, поэтому через публичный API Supabase (anon-ключ) они недоступны. Бесплатный проект
Supabase засыпает после недели без обращений — тогда его нужно разбудить кнопкой в панели Supabase.

### Безопасность и резервная копия

- **Сохраните копию `.env`** в надёжном месте. `MASTER_KEY` менять нельзя: им зашифрованы ключи
  в базе, без него их не восстановить (страница `/keys` предупредит, если ключи не расшифровываются).
- Сервер слушает только `127.0.0.1`: ни из интернета, ни из локальной сети он недоступен, попасть
  в дашборд можно только через SSH-туннель. Если понадобится открыть его по адресу в интернете —
  ставьте перед ним обратный прокси с HTTPS, не открывайте порт напрямую.
- После 5 неверных паролей вход блокируется на 30 секунд, дальше пауза удваивается (до часа).
- Сборщик не ходит по адресам внутренней сети (localhost, 192.168.x.x и т. п.), в том числе после
  переадресаций. Отключается переменной `ALLOW_PRIVATE_URLS=1` в `.env`.

### Scrapling — бесплатный обход защит

Необязателен, но без него защищённые сайты сразу тратят кредиты Firecrawl. Нужен Python 3.10+:

```bash
pip install "scrapling[shell] @ git+https://github.com/relaxcyber/Scrapling"
scrapling install      # скачивает браузер для скрытого режима
```

Если команда `scrapling` не в PATH (например, стоит в виртуальном окружении), укажите полный
путь в `.env`: `SCRAPLING_BIN=/путь/к/scrapling`. Страница `/collect` показывает, найден ли он.

Порядок каскада для страницы: прямой запрос → Scrapling с отпечатком Chrome → Scrapling со
скрытым браузером и решением проверки Cloudflare → Firecrawl.

### Ключи

По одному — формой на странице `/keys`. Пачкой — из файла, который не попадает в git:

```bash
cp keys.example.txt keys.txt   # вписать ключи
npm run keys:import -- keys.txt
```

Все ключи одного провайдера образуют общий пул: запросы (и аудит, и письма) берут тот,
у которого больше свободной квоты.

## Вариант: приложение на сервере

Приложение работает на сервере постоянно; с ноутбука вы открываете дашборд в браузере через
защищённый SSH-туннель. Наружу сервер ничего не открывает.

**На сервере** (Linux с systemd, Node.js 22.12+), один раз:

```bash
git clone https://github.com/relaxcyber/Parsing.git && cd Parsing
cp .env.example .env && nano .env    # DATABASE_URL, MASTER_KEY, DASHBOARD_PASSWORD
scripts/server.sh install            # сборка, миграции, автозапуск
```

Обновление после новых изменений — `scripts/server.sh update`. Ещё есть `status`, `logs`, `stop`.

**На ноутбуке** (Windows): скопируйте `desktop/Parsing.cmd` на рабочий стол. Двойной щелчок
открывает туннель к серверу и дашборд в браузере (http://127.0.0.1:3210). Окно с туннелем должно
оставаться открытым, пока вы работаете. Адрес сервера задан в первых строках файла. На ноутбуке
нужен только SSH (встроен в Windows 10/11), Node.js не нужен.

Без ярлыка то же самое делается вручную:
`ssh -N -L 3210:127.0.0.1:3000 lihih@ssh.n8nawsautobot.pp.ua` и открыть http://127.0.0.1:3210.
